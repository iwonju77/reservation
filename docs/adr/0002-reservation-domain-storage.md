# ADR 0002: 예약 도메인과 물리적 테이블 점유

- 상태: 승인된 개발 기준
- 날짜: 2026-11-06 (Asia/Taipei)

## 결정

예약 상태와 물리적 테이블 점유를 분리한다. 하나의 예약이 결합 테이블을 사용하면 `reservation_allocations`에 실제 테이블별 행을 생성한다. 각 행은 `[시작, 종료)` 형태의 PostgreSQL `tstzrange`를 저장한다.

활성 점유는 `(restaurant_id, table_id, occupied_period)` GiST exclusion constraint로 보호한다. `released_at`이 없는 행끼리 시간이 겹치면 DB가 `23P01` 오류로 거부한다. 종료시각과 다음 시작시각이 같은 예약은 허용한다. 예약을 취소·만료하거나 배정을 바꾸면 기존 행을 삭제하지 않고 `released_at`을 기록한다.

실제 착석은 `table_occupancies`에 따로 기록한다. 물리적 테이블마다 완료되지 않은 착석은 하나만 존재할 수 있다. 예약 스냅샷, 상태 이벤트, 멱등 요청, 감사 이력도 업무 데이터와 분리해 보관한다.

## 이유

애플리케이션의 사전 조회만으로 동시 요청을 막을 수 없다. 실제 테이블을 점유 단위로 사용하면 단독 예약과 2개·3개 결합 예약이 같은 DB 제약을 공유한다. 상태와 점유를 분리하면 취소·No-show·좌석 변경 이력을 보존하면서 사용 가능 좌석을 정확히 계산할 수 있다.

## 검증

실제 PostgreSQL 다중 연결에서 같은 마지막 테이블을 노린 10건 중 정확히 1건만 성공했다. 결합 예약과 단독 예약 충돌, 경계가 닿는 구간, 해제된 점유 재사용, 다른 매장의 테이블 참조, 실제 착석 중복, 정책 일정 중복을 통합 테스트한다.
