# ADR 0005: 예약 HOLD와 좌석 동시성

- 상태: 승인된 개발 기준
- 날짜: 2026-11-08 (Asia/Taipei)

## 결정

예약 접수는 가용성 조회 후 10분 HOLD를 생성하고 같은 예약 ID를 제출 단계에서 다음 상태로 전이한다. 일반 예약은 `CONFIRMED`, 직원 승인이 필요하면 `PENDING_APPROVAL`, 예약금이 필요하면 `PENDING_PAYMENT`가 된다. 예약금이 필요한 예약은 결제 성공 전 확정하지 않는다.

HOLD 생성은 예약 행, 정책 스냅샷, 실제 테이블별 점유, 상태 이벤트, outbox 이벤트, 만료 작업과 멱등 응답을 하나의 PostgreSQL 트랜잭션에 기록한다. 단독 테이블과 결합 테이블은 모두 실제 `table_id`별 `reservation_allocations`를 생성하며 기존 GiST exclusion constraint가 마지막 동시성 방어선이 된다.

정책 평가 결과에는 이용시간, 정리시간, 시작 간격, 예약 오픈 기간, 마감, 최소소비, 예약금과 승인 필요 여부를 포함한다. 점유 종료는 고객 이용 종료에 정리시간을 더한 시각이다. 영업시간, 특별휴무·특별영업, 매장·테이블 차단과 비활성 테이블을 후보 탐색에 반영한다.

## 동시성 순서

예약 생성은 매장 단위 shared advisory lock을, 정책 게시·영업시간 변경·테이블 비활성·예약 차단은 같은 키의 exclusive advisory lock을 사용한다. 설정 변경과 예약 생성이 동시에 실행돼 금지된 시간이나 좌석이 확정되는 상황을 막는다. 같은 고객 세션은 별도 advisory lock으로 직렬화하며 활성 HOLD를 세 개로 제한한다.

동일 멱등키와 동일 요청은 처음 생성한 HOLD 응답을 반환한다. 같은 키의 다른 요청은 거부한다. HOLD 소유권은 HttpOnly 익명 세션 쿠키로 확인하고 제출 시 예상 reservation version을 요구한다.

## 만료와 worker

worker는 `FOR UPDATE SKIP LOCKED`와 30초 lease로 만료 작업을 가져온다. 만료된 HOLD는 `EXPIRED`로 전이하고 점유를 해제하며 이벤트와 outbox를 기록한다. worker가 지연돼도 가용성 조회, HOLD 생성과 제출 요청 경로에서 만료 정리를 수행한다. 작업은 savepoint 단위로 실패를 기록하고 재시도 시각을 갱신한다.

## 검증

실제 PostgreSQL 다중 연결에서 마지막 테이블을 향한 20개 요청 중 하나만 성공하는지, 결합·단독 경쟁, 정리시간 경계, 멱등 재시도, 세션 HOLD 제한, 승인·결제 상태, 만료 후 재사용, worker lease, 설정 변경 영향과 게시 정책 일정 불변성을 검증한다.
